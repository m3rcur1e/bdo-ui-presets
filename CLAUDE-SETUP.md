# bdo-ui — инструкция по установке для Claude

Этот файл написан для ассистента (Claude Code), которому человек передал папку с `bdo-ui` и попросил поставить её у себя. Прочитай целиком, потом действуй.

## Что это

`bdo-ui` — библиотека и редактор раскладок интерфейса Black Desert Online. В игре всего три слота пресетов UI на семью. Тулза хранит сколько угодно раскладок на диске и подкладывает нужную в один из трёх игровых слотов. Есть GUI с перетаскиванием панелей и CLI.

Состав папки:

| Файл | Назначение |
|---|---|
| `main.py` | точка входа, CLI |
| `core.py` | разбор и запись файлов игры, библиотека, определение путей |
| `gui.py` | редактор на PySide6 |
| `panels.py` | имена панелей по индексам и их размеры |
| `bdo-ui.bat` | лаунчер для Windows |
| `requirements.txt` | зависимости (только PySide6) |

## Что нужно настроить

В большинстве случаев ничего, кроме установки Python и PySide6. Путь к настройкам игры определяется автоматически:

- **Windows:** `Документы\Black Desert` (учитывается перенос «Документов», например в OneDrive). Подходит и для Steam-версии, и для лаунчера Pearl Abyss.
- **Linux (Steam + Proton):** ищется по библиотекам Steam из `libraryfolders.vdf`, внутри `steamapps/compatdata/582660/pfx/drive_c/users/steamuser/Documents/Black Desert`.

Если автоопределение не сработало, путь указывается один раз и запоминается в `~/.bdo/bdo-ui.json` (на Windows `%USERPROFILE%\.bdo\bdo-ui.json`):

- **в редакторе:** при запуске сам появится диалог выбора папки; позже путь меняется кнопкой «Game folder…»;
- **в терминале:** `bdo-ui docs <путь>`; без аргумента команда показывает текущий путь и найден ли он.

Нужна папка `Black Desert`, в которой лежат `GameOption.txt` и `UserCache/`. Тулза примет и её родителя, и саму `UserCache`.

Порядок поиска: переменная окружения `BDO_DOCS` (если задана, перекрывает всё), затем сохранённый путь, затем автоопределение. Результат автоопределения не кешируется, он вычисляется при каждом запуске.

Вторая переменная, необязательная: `BDO_UI_LIB` — где хранить библиотеку. По умолчанию `~/.bdo/ui-presets` (на Windows `%USERPROFILE%\.bdo\ui-presets`).

## Шаги установки

1. Проверь Python: нужен 3.10 или новее (`python --version`).
2. Поставь зависимость из папки проекта: `pip install -r requirements.txt`.
3. Проверь, что тулза видит игру:
   - Windows: `bdo-ui.bat list`
   - Linux: `python3 main.py list`

   Ожидаемый вывод — список библиотеки (пустой) и три игровых слота с числом панелей и размером экрана.
4. Если вместо этого ошибка `game settings not found at ...`:
   - найди на машине папку `Black Desert` с файлом `GameOption.txt` и подпапкой `UserCache`;
   - выполни `bdo-ui docs "<путь к этой папке>"` и повтори `list`.
5. Сделай лаунчер, если человек хочет запускать одной командой:
   - Windows: `bdo-ui.bat` уже готов, можно сделать на него ярлык.
   - Linux: скрипт в `~/bin` или `~/.local/bin` с содержимым `exec python3 /путь/к/bdo-ui/main.py "$@"`.
6. Запусти редактор без аргументов и убедись, что окно открылось, слева видны игровые слоты.

## Что проверено, а что нет

- На Linux (Arch, Wayland, Steam + Proton) тулза проверена в работе: чтение, запись слота, запись скиллов, редактор.
- Ветки для Windows написаны, но на Windows ни разу не запускались. Непроверенные места: определение папки «Документы» через `SHGetKnownFolderPath`, проверка процесса через `tasklist`, размер окна игры через `EnumWindows`. Если что-то из этого упадёт или поведёт себя странно — чини в `core.py`, все платформенные развилки там помечены условием `WINDOWS`.
- Кнопка «Take from running game window» в диалоге «Screen…» на Linux работает только под Hyprland (через `hyprctl`). На других оконных менеджерах она скажет, что окно не найдено; размер экрана тогда вводится руками.

## Правила безопасности — соблюдай их

1. **Запись только при закрытой игре.** Игра держит пресеты и настройки персонажа в памяти и перезаписывает файлы. Запись при запущенной игре либо не подействует, либо будет затёрта — это проверено. Тулза сама отказывается писать, пока запущен `blackdesert64.exe`; не обходи этот запрет.
2. **Не редактируй файлы игры руками** в обход тулзы. Формат чувствителен к переводам строк (CRLF) и порядку строк; `core.py` сохраняет всё, кроме изменяемого слота, байт-в-байт.
3. **Бэкапы.** Перед каждой записью тулза кладёт копию изменяемого файла в `<библиотека>/.backups/` (хранятся последние 30 на семью). Скажи человеку, где они лежат.
4. **Первым делом сохрани текущие слоты в библиотеку**, до любых изменений:
   ```
   bdo-ui save "моя раскладка 1" 1
   bdo-ui save "моя раскладка 2" 2
   bdo-ui save "моя раскладка 3" 3
   ```
   Это только чтение, можно при запущенной игре. Имена спроси у человека.

## Как этим пользоваться

```
bdo-ui                       редактор
bdo-ui edit <имя>            редактор сразу на пресете из библиотеки
bdo-ui list                  библиотека и игровые слоты
bdo-ui save <имя> <1-3>      игровой слот -> библиотека
bdo-ui load <имя> <1-3>      библиотека -> игровой слот (игра закрыта)
bdo-ui skills <профиль>      скиллы в слоты персонажа (игра закрыта), --dry-run для просмотра
bdo-ui icons <профиль>       скачать иконки скиллов для редактора
bdo-ui chars                 персонажи семьи, последний игравший первым
bdo-ui docs [путь]           показать или задать папку настроек игры
bdo-ui --family <id> ...     другая семья; по умолчанию — та, на которой играли последней
```

Обычный сценарий смены персонажа:

1. Закрыть игру.
2. `bdo-ui load <имя> <слот>` или кнопка «Write to game slot» в редакторе.
3. Запустить игру, в режиме Edit UI загрузить этот слот.

Важно объяснить человеку: то, что стоит на экране прямо сейчас, и три слота пресетов — разные вещи. Тулза меняет только слоты; раскладка на экране сменится, когда человек сам нажмёт загрузку пресета в игре.

## Что нужно знать про данные

- **Раскладка привязана к размеру окна игры.** В пресете записан размер экрана в UI-единицах (физические пиксели окна, делённые на `uiScale` из `GameOption.txt`). Чужой пресет, сделанный под другое разрешение, сначала пересчитай: в редакторе «Screen…» — ввести свой размер, панели сохранят относительное положение. После этого проверь края экрана и наложения.
- **Раскладка общая на семью**, не на персонажа. В ней только позиции и видимость панелей.
- **Что лежит в слотах — отдельно.** Какие скиллы в квикслотах и в слотах отслеживания кулдауна, хранится в файле персонажа: `UserCache/<семья>/400/<id персонажа>/gameVariable.xml` (имя файла бывает и с маленькой `v`).
- **Имена панелей** взяты из декомпилированных скриптов клиента 2022 года. Панели с индексами 160 и выше появились позже и подписаны как `Panel N`.
- **Менять размер панелей нельзя**, только позицию и видимость.

## Запись библиотеки = раскладка + содержимое слотов

Одна запись библиотеки состоит из двух файлов с одинаковым именем:

- `<библиотека>/<имя>.xml` — раскладка панелей;
- `<библиотека>/skills/<имя>.json` — профиль: к какому персонажу относится запись и какие скиллы лежат у него в квикслотах и слотах кулдауна, плюс подписи-хоткеи.

Как они связаны:

- `bdo-ui save <имя> <слот>` сохраняет раскладку и сразу снимает содержимое слотов с персонажа, на котором играли последним. Другой персонаж — `--char <id>` (список: `bdo-ui chars`), без содержимого — `--no-skills`.
- В редакторе при первом сохранении слота под новым именем об этом спросит диалог. «Save as…» копирует профиль вместе с раскладкой, Rename и Delete действуют на оба файла.
- `bdo-ui load <имя> <слот>` пишет только раскладку и сообщает, если у персонажа в слотах сейчас не то, что сохранено. Вернуть сохранённое — флаг `--with-skills`; в редакторе после записи слота об этом спросит диалог. По умолчанию не восстанавливается намеренно: человек мог переставить скиллы в игре уже после сохранения.
- `bdo-ui skills <имя> --capture` перечитывает содержимое слотов с персонажа в профиль.
- В редакторе запись привязывается к персонажу кнопкой «Character…»: карточки персонажей в том же порядке, что на экране выбора в игре, с портретом, именем, классом и спеком, датой последнего захода и списком записей библиотеки, уже привязанных к персонажу. Текущий обведён рамкой. Выбор сразу перечитывает содержимое слотов с этого персонажа. Привязка видна в заголовке окна.
  - **Портрет** берётся из `FaceTexture/<id персонажа>.bmp` в папке настроек игры.
  - **Класс и спек** определяются по скиллам в слотах персонажа. Для этого один раз скачивается список скиллов всех классов с bdocodex.com (один запрос, около 5 МБ, кеш в `<библиотека>/icons/skills.json`). У персонажа с пустыми слотами класс неизвестен.
  - **Имя** игра локально не хранит, оно вводится один раз кнопкой «Name…» (или `bdo-ui chars --char <id> --name <имя>`) и лежит в `<библиотека>/characters.json`.
  - Удалённые персонажи скрыты, показываются галочкой внизу диалога; в терминале — `bdo-ui chars --all`.

**Иконки скиллов в редакторе.** Если у записи есть профиль, редактор рисует в слотах иконки скиллов (галочка «Skill icons»). Иконки скачиваются с bdocodex.com по id скилла и кешируются в `<библиотека>/icons/`: кнопка «Get icons» или `bdo-ui icons <имя>`. Это единственное место, где тулза ходит в сеть.

## Профили скиллов

Команда `bdo-ui skills <профиль>` читает `<библиотека>/skills/<профиль>.json`:

```json
{
  "family": "<id семьи>",
  "char": "<id персонажа>",
  "cooldown": {"0": 4592, "1": 4596},
  "quick": {"1": 4595, "2": 161},
  "memo": {"4592": "SHIFT+Lmb", "4583": "E"},
  "names": {"4592": "Prime: Midnight Stinger"}
}
```

- `cooldown` — номер слота отслеживания кулдауна (0–19) → id скилла.
- `quick` — номер квикслота, как он подписан в игре (1–20; слот 10 — это клавиша `0`) → id скилла; `null` очищает слот. В файле игры тот же слот хранится как `Key` на единицу меньше, тулза пересчитывает сама. Слоты, не упомянутые в профиле (в том числе с предметами), не трогаются.
- `memo` — подпись на слоте кулдауна (обычно хоткей) → по id скилла. Игра хранит подписи под id **базового скилла первого ранга** (для `Prime:`-скиллов — под id исходного, донаследного скилла). Можно указать id первого ранга самого Prime-скилла: подпись появится, а при следующем сохранении игра сама перепишет ключ на базовый. Чтобы повторный запуск профиля ничего не менял, после первой сессии перенеси в профиль те id, которые игра оставила в секции `SkillCoolTimeMemo` файла персонажа. Уже существующие подписи других скиллов не трогаются.
- `names` — необязательные подписи для вывода.

Флаг `--only cooldown,quick,memo` ограничивает запись выбранными частями — удобно, чтобы добавить подписи и не перетереть слоты, которые человек успел переставить в игре.

Профиль с чужой учётки не подойдёт как есть: `family` и `char` у каждого свои.

Как найти свои значения:

- **Семья** — имя числовой папки в `UserCache/`.
- **Персонаж** — папки `400/4000…` внутри семьи. Нужного проще всего определить по времени изменения файла сразу после выхода из игры на этом персонаже.
- **id скилла** — номер из адреса страницы скилла на bdocodex.com (`/us/skill/<id>/`). Нужен id именно того ранга, который изучен у персонажа; для наследия — варианты `Prime:` и `Succession:`. Не полагайся на память о номерах и названиях скиллов, сверяй по сайту: игра часто меняется.

Перед записью всегда показывай человеку `bdo-ui skills <профиль> --dry-run` и получай подтверждение.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `game settings not found` | путь: `bdo-ui docs` покажет, где ищет; задать — `bdo-ui docs <путь>` |
| `no UISettingPreset block` | в этой семье ещё ни разу не сохраняли пресет в игре; сохрани любой слот в Edit UI и повтори |
| `Black Desert is running` при закрытой игре | остался висеть процесс `blackdesert64.exe`, заверши его |
| `... is locked by another program` (Windows) | файл держит игра или антивирус |
| слот записан, а в игре старая раскладка | пресет не загрузили в Edit UI, либо запись шла при запущенной игре |
| окно редактора не открывается | не установлен PySide6 или слишком старый Python |
